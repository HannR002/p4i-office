# Decision Log — P4I Office v1.0
## Pencatatan Keputusan Teknis, Mitigasi Risiko, dan Rekonsiliasi Dokumen

| ID | Tanggal | Topik | Keputusan | Rasional & Mitigasi |
|---|---|---|---|---|
| **DEC-001** | 2026-10-28 | Isolasi Proyek | Membangun proyek mandiri di direktori `d:\p4i-office` tanpa menyentuh repositori `p4i-corporate-hub` atau `p4i-webgis`. | Menjamin tidak terjadi polusi kode atau kebocoran konfigurasi antar sistem yayasan. |
| **DEC-002** | 2026-10-28 | Ketiadaan PostgreSQL Lokal | Menyiapkan layer koneksi DB adaptif: migrasi SQL murni PostgreSQL (`db/migrations/0001_sprint1a_core.sql`), abstraksi repository, dan pelaporan status pengujian integrasi database riil sebagai `BLOCKED (PostgreSQL Service Offline)` daripada mengarang status `PASS`. | Mematuhi aturan ketat transparansi pengujian pada prompt master; integritas logika bisnis tetap diuji via unit test menyeluruh. |
| **DEC-003** | 2026-10-28 | Kebijakan Penomoran Resmi | Mengunci mati fitur penomoran otomatis (`FEATURE_NUMBERING_ACTIVE = false`) dan menetapkan `is_active = false` pada seluruh tabel kebijakan penomoran. | Dokumen D-01 s.d. D-03 pada paket Sprint 0 belum disahkan oleh Pengurus. Mencegah terbitnya nomor surat ilegal atau inkonsisten. |
| **DEC-004** | 2026-10-28 | Pemisahan RBAC & Mandat Legal | Peran teknis `SYSTEM_ADMIN` tidak diberi izin untuk menyetujui (`approve`) atau menandatangani (`sign`) surat. | Sesuai klausul SRS 3.0: administrator teknis tidak boleh memiliki kuasa administratif legal tanpa mandat tertulis terverifikasi. |
| **DEC-005** | 2026-10-28 | Ketiadaan Dukungan MFA | Menandai MFA sebagai GAP keamanan kritis yang memblokir rilis admin produksi, bukan mengklaim telah selesai. | Sprint 1A berfokus pada fondasi sesi dan RBAC. MFA akan dijadwalkan pada sprint keamanan lanjutan sebelum go-live. |
| **DEC-006** | 2026-10-28 | Watermark Pratinjau | Setiap pratinjau draf surat wajib menampilkan watermark teks dan badge jelas: **"DRAF — BELUM RESMI"** serta header placeholder berlabel **"DATA BELUM DIVERIFIKASI"**. | Menghindari penggunaan pratinjau digital sebagai surat edaran resmi palsu oleh staf internal. |
| **DEC-007** | 2026-10-29 | Arsitektur Repository DB Adaptif & Row-Locking | Membangun implementasi penuh `PostgresDatabaseStore` berbasis `pg.Pool`, query terparameterisasi `$1..$n`, transaksi ACID, row locking `FOR UPDATE` saat revisi, dengan `MemoryDatabaseStore` sebagai adapter fail-safe terisolasi saat daemon DB offline. | Memenuhi target Sprint 1B tanpa mengorbankan portabilitas lokal dan tanpa membuat laporan mock palsu. |
| **DEC-008** | 2026-10-29 | Pelacakan Migrasi Idempotent | Mengintroduksi tabel `schema_migrations` pada `0002_sprint1b_persistence.sql` dan eksekutor migrasi `scripts/migrate.mjs` ber-checksum SHA-256. | Menjamin migrasi database dapat dijalankan ulang secara aman dan idempotent tanpa merusak skema atau data eksisting. |
| **DEC-009** | 2026-10-29 | Otorisasi Kepemilikan Surat & Revokasi Real-Time | Memberlakukan kepemilikan draf (staf hanya dapat menyunting/mengajukan draf buatannya sendiri), isolasi klasifikasi `CONFIDENTIAL`, dan pengecekan status akun ke DB pada setiap request sesi. | Mencegah staf lain memodifikasi atau membaca draf rahasia pihak lain, serta menghentikan akses akun `DISABLED` seketika. |
| **DEC-010** | 2026-10-29 | Runtime PostgreSQL Native Portabel (Tanpa Modifikasi OS Invasif) | Menjalankan native binary PostgreSQL x64 via `embedded-postgres` (PostgreSQL 18.4) di user-space lokal (`.data/postgres`) pada `127.0.0.1:5432`. | Menghindari kebutuhan hak administrator Windows atau Docker Desktop, mematuhi larangan modifikasi sistem OS tanpa izin, dan menghadirkan PostgreSQL riil tanpa mock palsu. |
| **DEC-011** | 2026-10-29 | Eliminasi Silent Memory Fallback & Penegakan Strict Routing | Saat PostgreSQL offline, sistem langsung melempar `DatabaseUnavailableError` (health: `UNAVAILABLE`). Mode `SIMULATION` hanya aktif jika `DB_SIMULATION=true` & `NODE_ENV=test`, mutlak dilarang di production. | Menghilangkan silent fallback ke memori yang berisiko menghilangkan data transaksi secara tak terdeteksi. |
| **DEC-012** | 2026-10-29 | Normalisasi Penanganan Tipe Data DATE (OID 1082) | Menetapkan pg type parser OID 1082 agar mengembalikan format string `YYYY-MM-DD` murni tanpa konversi zona waktu lokal. | Menghilangkan distorsi pergeseran tanggal (date-shifting) akibat perbedaan UTC dan GMT+7 saat backup, serialize, dan restore. |
| **DEC-013** | 2026-10-29 | Mekanisme Backup dan Restore Berbasis Transaksi ACID & SHA-256 Round-Trip | Menyediakan `scripts/backup-db.mjs` dan `scripts/restore-db.mjs` berurutan topologis dengan verifikasi hash SHA-256 dan restorasi ke database kedua (`p4i_office_restore_test`). | Memenuhi Acceptance Gate DB-07 dengan bukti kesamaan bit-for-bit data hasil restorasi tanpa risiko korupsi. |
| **DEC-014** | 2026-10-29 | Penegakan Exit Code Non-Zero pada Seluruh Skrip Infrastruktur | Memperbaiki `scripts/migrate.mjs` dan `scripts/seed-test.mjs` agar memanggil `process.exit(1)` saat terjadi kegagalan koneksi atau eksekusi SQL. | Memastikan kegagalan database tidak tersamar sebagai status sukses pada pipeline pengujian otomatis. |
| **DEC-015** | 2026-10-29 | Model State Machine Persetujuan Surat Internal (Sprint 2) | Menerapkan state machine: `DRAFT → SUBMITTED → IN_REVIEW → APPROVED`, bercabang ke `CHANGES_REQUESTED` dan `REJECTED`, dengan siklus kembali `CHANGES_REQUESTED → DRAFT → SUBMITTED`. | Menjamin alur pemeriksaan internal terstruktur tanpa mengaktifkan nomor surat resmi. |
| **DEC-016** | 2026-10-29 | Pengikatan Kriptografis dan Mandat Pejabat (Hash Binding & Mandates) | Keputusan reviewer mengikat `letter_id`, `revision_id`, `content_sha256`, `reviewer_id`, dan `mandate_id` (nomor SK penetapan). | Mencegah persetujuan draf yang telah diubah secara diam-diam dan memastikan akuntabilitas kewenangan pejabat. |
| **DEC-017** | 2026-10-29 | Penegakan Aturan Anti Self-Approval & Anti-Stale Approval | Backend menolak secara mutlak (`403 Forbidden`) jika pembuat draf mencoba menyetujui suratnya sendiri, dan menolak (`409 Conflict`) jika versi draf bertambah setelah diajukan. | Memenuhi prinsip segregation of duties dan mencegah race condition / stale review. |
| **DEC-018** | 2026-10-29 | Pembaruan Pipeline Backup-Restore 15 Tabel Termasuk Tabel Alur Kerja | Menambahkan tabel alur kerja (`signatory_mandates`, `approval_requests`, `approval_steps`, `letter_status_history`) dalam topological order dengan serialisasi deterministik. | Mempertahankan bukti verifikasi integritas data 100% bit-for-bit SHA-256 pada database riil. |
| **DEC-019** | 2026-10-30 | Migrasi Strategis ke Laravel & Kesiapan Hosting Hostinger 24 Jam (Sprint M0) | Mengadopsi framework Laravel 10.x LTS + Blade + Livewire 3 + Tailwind CSS pada workspace paralel `D:\p4i-office-laravel` untuk target deployment Hostinger 24/7 tanpa merusak repositori lama `D:\p4i-office`. | Memenuhi arahan pemilik proyek untuk keandalan operasional yayasan pada hosting terkelola dengan ekosistem native PHP. |
| **DEC-020** | 2026-10-30 | Pemetaan Basis Data MariaDB InnoDB & Isolasi Document Root (Sprint M0) | Menetapkan MariaDB 10.4+ InnoDB dengan row-level locking (`lockForUpdate`), primary key UUID (`CHAR(36)`), dan pemisahan fisik kode aplikasi di luar `public_html/`. | Menjamin konsistensi transaksi ACID, auditability naskah, serta mencegah kebocoran konfigurasi `.env` pada lingkungan shared/cloud hosting. |
